# 開發細節決定

本文件記錄開發過程中確定、但規格本文未寫到的細節，效力等同規格（見 spec 第 9 節）。
與規格本文衝突時以規格為準；新增或修改須經使用者確認。

## Phase 1

### 日記排序（補充 spec 3.1）

- 日期新的在上；同一天內依建立時間，後寫的在上。

### 新增與編輯（補充 spec 3.1）

- 日期選擇器預設為使用者裝置時區的今天；日期以 `YYYY-MM-DD` 儲存與顯示。
- 日期被清空時不儲存，顯示「請選擇日期」。
- 日期最晚只能選到今天（依使用者裝置時區），新增與編輯皆適用；儲存時若日期晚於今天，不儲存並顯示「日期不能晚於今天」，保留已輸入的內容。已存在的未來日期日記照常顯示，不另外處理。
- 內容依使用者輸入原樣保存，不去除前後空白。
- 新增日記儲存後，跳到該篇日記頁（`/entry/:id`）；按上一頁回到列表。
- 編輯日記儲存後，留在原頁並顯示「已儲存」。
- 編輯時內容改成空白，不儲存，顯示提示，保留原本內容。
- 離開頁面時若有未儲存的修改，不另外提醒。

### 刪除（補充 spec 3.1）

- 刪除前使用瀏覽器內建確認視窗；確認後回到主畫面。

### 畫面

- 主畫面為日記列表，列表預覽最多 80 字，超過以「…」結尾。
- 日記頁路徑為 `/entry/:id`，新增頁為 `/entry/new`。
- 開啟不存在或已刪除的日記，顯示「找不到這篇日記」。
- 不存在的網址只顯示標題，不另做 404 頁面。

### 首次使用說明（補充 spec 3.5）

- 只在進入主畫面時判斷是否顯示說明頁；直接開啟其他網址（例如 `/entry/new`）不導向。
- 讀取設定失敗時不導向，照常顯示列表；按「開始使用」時寫入失敗，仍回到主畫面，本次開啟期間不再導向。

### AI 批改結果顯示（補充 spec 4.2、5.4）

- 文法錯誤為空時顯示「無錯誤」；不通順或易誤會的句子、更道地的說法為空時顯示「無」。
- 原文與修改之間以「→」分隔；多個推薦說法以「／」分隔。
- 修改後全文的 `**` 依出現順序兩兩配對，配對之間顯示為粗體；無法配對的 `**` 照原樣顯示為文字，不遺失任何文字。

### 部署與測試（補充 spec 2.3、第 7 節）

- 子路徑重新整理的 404 問題：build 後複製 `index.html` 為 `404.html`。
- GitHub Actions 部署前執行單元測試與 E2E，任一失敗不部署；CI 的 E2E 對正式 build 執行，使用模擬 GitHub Pages 的本機伺服器（`scripts/pages-server.js`），以驗證 `404.html`；Node 版本固定為 22。
- E2E 使用專屬 port 5199，不沿用已開啟的伺服器。
- 單元測試固定在 `Asia/Taipei` 時區執行，確保 UTC 環境也能測出時區錯誤。

## Phase 2

以下於 Phase 1 結束後、Phase 2 開始前確認。

### 部署網域（補充 spec 2.3、5.4）

- 接受 `https://<帳號>.github.io` 同網域共用瀏覽器資料的風險：同一帳號底下的其他 GitHub Pages 專案在技術上可讀寫本 App 的 IndexedDB（含 Gemini API key）。維持現有網址，不改用自訂網域。確認時該帳號只有本專案啟用 Pages。

### 日記語言（補充 spec 2.2、4.1、5.5）

- `language` 存值：`auto`（自動判斷）、`日文`、`英文`，或自行輸入的語言文字。
- 語言選單放在日記編輯頁，與日期、內容一起，預設「自動判斷」；選項依序為自動判斷、日文、英文、語言清單中的語言、其他。
- 選「其他」時輸入的文字去除前後空白後儲存；未輸入或只有空白時不儲存，顯示「請輸入日記語言」，保留已輸入的內容。
- 儲存日記時，自行輸入的語言自動加入語言清單；與清單中已有的語言相同時不重複加入；輸入「日文」「英文」時視同選擇該選項，不加入清單。
- 語言清單每個項目記錄名稱、`updatedAt`、刪除記號與刪除時間，從 Phase 2 起就這樣存，供 Phase 4 同步。
- 在設定頁刪除語言時採軟刪除；再次輸入同名語言時，恢復原項目並更新 `updatedAt`，不新增第二筆。
- 語言刪除後，已使用該語言的日記保持原值，照常顯示與批改。

### 首次使用說明（補充 spec 3.5）

- 說明頁不放「AI 批改」按鈕，範例的批改結果維持靜態展示。
- 「使用說明」入口改放到主畫面右上角的選單，選項為「設定」與「使用說明」（spec 3.5 已修改）。

### Gemini 模型（補充 spec 3.6、5.1）

- 存好 API key 後，以該 key 查詢可用模型，只列出能生成文字的 Gemini 模型。
- 尚未選擇時，自動選擇清單中第一個名稱含「flash」的模型並儲存，使用者可以更換。
- 每次打開設定頁都重新查詢；原本選的模型不在清單中時，提示使用者重新選擇。
- 查詢失敗時顯示錯誤訊息與「重新查詢」按鈕；原本選的模型保留，照常可批改。

### 設定頁（補充 spec 3.6）

- API key 欄位預設隱藏（同密碼欄），旁邊有「顯示」按鈕；刪除 API key 不跳確認視窗。
- 刪除語言清單的項目不跳確認視窗。
- 語言名稱去除前後空白後完全相同才視為同一個語言（區分大小寫）。
- 舊日記的語言已從清單刪除時，打開該篇日記，語言選單仍顯示該語言並維持選取；其他日記的選單不顯示；儲存時不把它加回清單。

### AI 批改（補充 spec 3.2、5.3）

- 日記有未儲存的修改時按「AI 批改」，不送出，顯示「請先儲存日記再批改」；尚未儲存過的新日記不顯示批改按鈕。
- 批改後又修改日記，舊批改結果照常顯示，並標出批改時間；使用者自行決定是否重新批改。
- 批改中離開頁面，結果回來後仍存進該篇日記：只寫入 `analysis` 並更新 `updatedAt`，不覆蓋期間的其他修改；該篇已被刪除時丟棄結果。
- 錯誤訊息：
  - API key 無效：「API key 無效，請到設定頁確認。」
  - 額度用完：「已達 Gemini 使用額度上限，請稍後再試。」
  - 網路問題：「無法連線到 Gemini，請檢查網路後再試一次。」
  - 回傳格式錯誤：「AI 回傳的格式不正確，請再試一次。」
  - 模型無法使用：「所選的模型已無法使用，請到設定頁重新選擇。」
  - 其他錯誤：「批改失敗，請稍後再試一次。」
  - 未設定 API key：「請先到設定頁設定 Gemini API key。」並附設定頁連結。
  - 未設定模型：「請先到設定頁選擇 Gemini 模型。」並附設定頁連結。
- 日記內容被 Gemini 安全機制擋下時，同樣顯示「AI 回傳的格式不正確，請再試一次。」
- 編輯儲存時，若該篇已在其他分頁刪除，不寫入，顯示「這篇日記已被刪除，無法儲存。」並保留已輸入的內容。

### 畫面（補充 spec 3.2、3.5）

- 畫面寬度 768px 以上時，批改結果與日記左右並排；較窄時上下排列。
- 「設定／使用說明」選單只放在主畫面。
