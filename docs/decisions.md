# 開發細節決定

本文件記錄開發過程中確定、但規格本文未寫到的細節，效力等同規格（見 spec 第 9 節）。
與規格本文衝突時以規格為準；新增或修改須經使用者確認。

## Phase 1

### 日記排序（補充 spec 3.1）

- 日期新的在上；同一天內依建立時間，後寫的在上。

### 新增與編輯（補充 spec 3.1）

- 日期選擇器預設為使用者裝置時區的今天；日期以 `YYYY-MM-DD` 儲存與顯示。
- 日期被清空時不儲存，顯示「請選擇日期」。
- 日期最晚只能選到今天（依使用者裝置時區），新增與編輯皆適用；儲存時若日期晚於今天，不儲存並顯示「日期不能晚於今天」，保留已輸入的內容。已存在的未來日期日記照常顯示，不另外處理。
- 內容依使用者輸入原樣保存，不去除前後空白。
- 新增日記儲存後，跳到該篇日記頁（`/entry/:id`）；按上一頁回到列表。
- 編輯日記儲存後，留在原頁並顯示「已儲存」。
- 編輯時內容改成空白，不儲存，顯示提示，保留原本內容。
- 離開頁面時若有未儲存的修改，不另外提醒。

### 刪除（補充 spec 3.1）

- 刪除前使用瀏覽器內建確認視窗；確認後回到主畫面。

### 畫面

- 主畫面為日記列表，列表預覽最多 80 字，超過以「…」結尾。
- 日記頁路徑為 `/entry/:id`，新增頁為 `/entry/new`。
- 開啟不存在或已刪除的日記，顯示「找不到這篇日記」。
- 不存在的網址只顯示標題，不另做 404 頁面。

### 首次使用說明（補充 spec 3.5）

- 只在進入主畫面時判斷是否顯示說明頁；直接開啟其他網址（例如 `/entry/new`）不導向。
- 讀取設定失敗時不導向，照常顯示列表；按「開始使用」時寫入失敗，仍回到主畫面，本次開啟期間不再導向。

### AI 批改結果顯示（補充 spec 4.2、5.4）

- 文法錯誤為空時顯示「無錯誤」；不通順或易誤會的句子、更道地的說法為空時顯示「無」。
- 原文與修改之間以「→」分隔；多個推薦說法以「／」分隔。
- 修改後全文的 `**` 依出現順序兩兩配對，配對之間顯示為粗體；無法配對的 `**` 照原樣顯示為文字，不遺失任何文字。

### 部署與測試（補充 spec 2.3、第 7 節）

- 子路徑重新整理的 404 問題：build 後複製 `index.html` 為 `404.html`。
- GitHub Actions 部署前執行單元測試與 E2E，任一失敗不部署；CI 的 E2E 對正式 build 執行，使用模擬 GitHub Pages 的本機伺服器（`scripts/pages-server.js`），以驗證 `404.html`；Node 版本固定為 22。
- E2E 使用專屬 port 5199，不沿用已開啟的伺服器。
- 單元測試固定在 `Asia/Taipei` 時區執行，確保 UTC 環境也能測出時區錯誤。

## Phase 2

以下於 Phase 1 結束後、Phase 2 開始前確認。

### 部署網域（補充 spec 2.3、5.4）

- 接受 `https://<帳號>.github.io` 同網域共用瀏覽器資料的風險：同一帳號底下的其他 GitHub Pages 專案在技術上可讀寫本 App 的 IndexedDB（含 Gemini API key）。維持現有網址，不改用自訂網域。確認時該帳號只有本專案啟用 Pages。

### 日記語言（補充 spec 2.2、4.1、5.5）

- `language` 存值：`auto`（自動判斷）、`日文`、`英文`，或自行輸入的語言文字。
- 語言選單放在日記編輯頁，與日期、內容一起，預設「自動判斷」；選項依序為自動判斷、日文、英文、語言清單中的語言、其他。
- 選「其他」時輸入的文字去除前後空白後儲存；未輸入或只有空白時不儲存，顯示「請輸入日記語言」，保留已輸入的內容。
- 選「其他」並輸入語言後，按「加入」或在輸入框按 Enter，立即加入語言清單並選取；日記還沒儲存也會加入；與清單中已有的語言相同時不重複加入；輸入「日文」「英文」時視同選擇該選項，不加入清單。
- 語言清單每個項目記錄名稱、`updatedAt`、刪除記號與刪除時間，從 Phase 2 起就這樣存，供 Phase 4 同步。
- 在設定頁刪除語言時採軟刪除；再次輸入同名語言時，恢復原項目並更新 `updatedAt`，不新增第二筆。
- 語言刪除後，已使用該語言的日記保持原值，照常顯示與批改。

### 首次使用說明（補充 spec 3.5）

- 說明頁不放「AI 批改」按鈕，範例的批改結果維持靜態展示。
- 「設定」與「使用說明」入口放在畫面頂部的固定列（spec 3.5 已修改，配置見下方「畫面」）。

### Gemini 模型（補充 spec 3.6、5.1）

- 存好 API key 後，以該 key 查詢可用模型，只列出正式版的主要文字模型（`gemini-<版本>-pro`、`-flash`、`-flash-lite`，可帶版本號），不列 preview、exp 與 `-latest`；篩選後沒有任何模型時，改為列出所有能生成文字的 Gemini 模型。
- 尚未選擇時，自動選擇版本最新的正式版 Flash 模型並儲存，使用者可以更換：flash 與 flash-lite 都算 Flash；先比版本號（新者優先），同版本時 flash 優先於 flash-lite、不帶 `-NNN` 的名稱優先；清單中沒有可依版本比較的 Flash 模型時，改選第一個名稱含「flash」的模型。
- 每次打開設定頁都重新查詢；原本選的模型被篩選隱藏但仍可使用時，保留為額外選項、不提示；不在可用模型中時，提示使用者重新選擇。
- 查詢失敗時，錯誤訊息與「重新確認」顯示在 API key 區塊，模型區塊隱藏；原本選的模型保留，照常可批改。

### 設定頁（補充 spec 3.6）

- API key 欄位預設隱藏（同密碼欄），旁邊有「顯示」按鈕；刪除 API key 不跳確認視窗。
- 刪除語言清單的項目不跳確認視窗。
- API key 區塊顯示 key 是否可用：「正在確認 API key…」、「API key 可以使用」、「API key 無效，請確認後重新儲存。」、「無法確認 API key，請檢查網路後再試一次。」（附「重新確認」）；其他失敗（額度用完、伺服器錯誤等）顯示「無法確認 API key，請稍後再試。」（附「重新確認」）；key 無效時不顯示「重新確認」；和查詢模型清單共用同一次請求。key 無效時照樣儲存，模型區塊不再重複顯示 key 無效的訊息。
- 「如何取得 API key」預設收起，按「？如何取得」展開或收起；尚未設定 key 時預設展開。
- 語言名稱去除前後空白後完全相同才視為同一個語言（區分大小寫）。
- 舊日記的語言已從清單刪除時，打開該篇日記，語言選單仍顯示該語言並維持選取；其他日記的選單不顯示；儲存時不把它加回清單。

### AI 批改（補充 spec 3.2、5.3）

- 日記有未儲存的修改時按「AI 批改」，不送出，顯示「請先儲存日記再批改」；尚未儲存過的新日記不顯示批改按鈕。
- 批改後又修改日記，舊批改結果照常顯示，並標出批改時間；使用者自行決定是否重新批改。
- 批改中離開頁面，結果回來後仍存進該篇日記：只寫入 `analysis` 並更新 `updatedAt`，不覆蓋期間的其他修改；該篇已被刪除時丟棄結果。
- 錯誤訊息：
  - API key 無效：「API key 無效，請到設定頁確認。」
  - 額度用完：「已達 Gemini 使用額度上限，請稍後再試。」
  - 網路問題：「無法連線到 Gemini，請檢查網路後再試一次。」
  - 回傳格式錯誤：「AI 回傳的格式不正確，請再試一次。」
  - 模型無法使用：「所選的模型已無法使用，請到設定頁重新選擇。」
  - 其他錯誤：「批改失敗，請稍後再試一次。」
  - 未設定 API key：「請先到設定頁設定 Gemini API key。」並附設定頁連結。
  - 未設定模型：「請先到設定頁選擇 Gemini 模型。」並附設定頁連結。
- 日記內容被 Gemini 安全機制擋下時，同樣顯示「AI 回傳的格式不正確，請再試一次。」
- 編輯儲存時，若該篇已在其他分頁刪除，不寫入，顯示「這篇日記已被刪除，無法儲存。」並保留已輸入的內容。

### 畫面（補充 spec 3.2、3.5）

- 畫面寬度 768px 以上時，批改結果與日記左右並排；較窄時上下排列。
- 每一頁頂部固定一列：左邊是「←」返回（設定頁、日記頁、新增頁才有；日記頁、新增頁與設定頁都回到進入前的 App 內頁面，直接開啟時回主畫面（Phase 3 修改）），中間是 App 名稱（回主畫面），右邊是「設定」與「使用說明」圖示按鈕（設定頁不顯示「設定」）。說明頁的頂部列右邊只放「開始使用」。
- 畫面寬度 768px 以上時，批改結果區固定在畫面上，高度為畫面扣掉頂部列，內容在區內捲動；較窄時整頁捲動。
- 編輯頁的日期與語言放在同一行；選「其他」時，「語言名稱」與「加入」放在下一行。
- 日記內容框至少 12 行高，隨內容自動長高，不在框內捲動。

## Phase 3

以下於 Phase 3 開始前確認。

### 日曆（補充 spec 3.3）

- 一週從星期日開始；標題顯示「2026 年 10 月」，兩側有「‹」「›」切換上下個月，另有「今天」回到本月；不限制可切換的範圍。
- 打開主畫面時顯示本月；今天以外框標示。
- 每月 1 號之前與月底之後的格子留白，不顯示其他月份的日期。
- 有日記（未刪除）的日期以底色圓圈標示，不顯示篇數。
- 只有有日記的日期可以點選；沒有日記的日期不能點，也沒有反應。
- 點選日期後，主畫面的日記列表只顯示當天，標題改為「10月18日 的日記」，旁邊有「顯示全部」；再點同一天或按「顯示全部」回到完整列表。
- 選取的日期與月份記在網址（例如 `/?month=2026-10&date=2026-10-18`），重新整理或從日記頁返回後保留。
- 畫面寬度 768px 以上時，日曆在列表左邊；較窄時在列表上方。

## Phase 4

以下於 Phase 4 開始前確認。前置作業（spec 8.5）：OAuth 用戶端已建立，維持「測試」發布狀態，`drive.appdata` 為非機密範圍。

### 同步（補充 spec 3.4、6）

- API key 與選擇的模型各自記錄修改時間，同步時以較新的為準；在一台裝置刪除 key，也會同步到其他裝置。
- 會同步的資料有任何變動都自動同步：儲存或刪除日記、批改結果存入、加入或刪除語言、修改 API key 或模型；短時間內多次變動合併成一次（約等 2 秒）。另外在開啟 App、按手動同步、網路恢復時也會同步。
- 登入後，頂部列右側顯示雲朵圖示，用形狀與顏色表示「同步中／已同步／同步失敗」，點圖示進設定頁；設定頁顯示文字狀態、上次同步時間與「立即同步」按鈕。
- 設定頁只顯示「已登入」，不顯示 Google 帳號。
- 登出只停止同步，本機與 Drive 上的資料都不刪除。
- 授權過期時，先在背景嘗試重新取得；失敗時顯示「同步失敗」與「Google 登入已過期，請重新登入。」，附「重新登入」按鈕。
- 正在編輯的日記被另一台裝置修改並同步過來時，不另外提示，依「最後修改的為準」處理。

- App 自動選擇的模型，修改時間記為 1970 年，不會蓋掉在其他裝置手動選擇的模型；使用者手動更換時才記錄當下時間。Phase 4 之前存的 API key 與模型沒有修改時間，同樣視為 1970 年。
- Drive 上的同步資料無法讀取（格式錯誤或由較新版本的 App 寫入）時，暫停同步，本機與 Drive 都不寫入，顯示「Google Drive 上的同步資料無法讀取，為避免資料遺失已暫停同步。」
- 其他訊息：離線或網路問題「無法連線到 Google Drive，恢復網路後會自動同步。」；Drive 額度或暫時無法使用「Google Drive 暫時無法使用，請稍後再試。」；其他同步錯誤「同步失敗，請稍後再試。」；登入失敗「無法登入 Google，請再試一次。」；登出失敗「無法登出，請重新整理頁面後再試一次。」
- 打開設定頁的「Google Drive 同步」區塊時即先載入 Google 登入程式，讓第一次登入的視窗不被瀏覽器擋下；沒有打開設定頁的使用者不會連到 Google。
- 同步進行中登出時，之後不再寫入本機或 Drive。
- 登出時撤銷授權；登入過期時也可以直接登出。
- 同步資料存成 App 專屬資料夾中的單一 JSON 檔（`nikki-ai-sync.json`），包含日記（含刪除記號）、語言清單、API key 與模型；不含「已看過說明」、Google 授權與上次同步時間。

### 設定頁（修改 Phase 2）

- API key 說明改為：「API key 存在這個瀏覽器；登入 Google 後，也會同步到你 Google Drive 中只有這個 App 看得到的資料夾。只用來呼叫 Gemini，不會傳送到其他地方。」


## 專案完成後的修改

### 主畫面列表分組（補充 spec 3.1）

- 完整列表依「今天」「昨天」與月份分組，月份標題含年份（例如「2026 年 10 月」）；沒有日記的分組不顯示。
- 分組內的排序不變；每篇日記仍顯示完整日期（`YYYY-MM-DD`）。
- 「今天」「昨天」依使用者裝置時區判斷，於打開主畫面時決定。
- 日期晚於今天的日記歸入所屬月份。
- 在日曆選取日期時只顯示當天，不分組。

### 隱私權政策（為 OAuth 正式發布準備）

- 隱私權政策為靜態網頁 `privacy.html`（網址 `/nikki-ai/privacy.html`），不經 App 路由，讓 GitHub Pages 回傳 200、不需執行 JavaScript 即可閱讀；同一頁中文在前、英文在後。
- 內容以該檔為準；修改內容須經使用者確認。新增分析或追蹤工具前，須先修改隱私權政策。
- 聯絡方式為 GitHub Issues（不公開 email）。
- 連結放在說明頁最下方，以及設定頁「Google Drive 同步」區塊的說明文字中。

### 版號

- 採語意化版本 `主.次.修`：新功能或使用回饋的修改加次版號，只修錯誤加修訂號；`package.json` 的 `version` 為唯一來源。
- 每次合併到 `main` 並上線，在合併 commit 打 tag（例如 `v1.1.0`），並建立中文 GitHub Release，內容整理自該次 PR。
- 補打過去的版本：Phase 1～4 為 v0.1.0～v0.4.0，專案完成（PR #5）為 v1.0.0。
- 設定頁最下方以灰色小字顯示「版本 x.y.z」。
