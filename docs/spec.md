# 外語學習日記 App 規格

本文件是開發時的正式規格。規格沒寫到、或規格之間有矛盾的地方，一律停下來詢問使用者，不要自行決定。

開發流程、角色分工、分支與 commit 規則見 `docs/WORKFLOW.md`。本文件只記載這個專案特有的內容。

---

## 1. 概述

讓外語學習者透過寫外語日記練習外語，並結合 AI 檢查與建議，幫助使用者學習正確且道地的表達方式。

要解決的問題：省去把日記複製到 ChatGPT 等對話視窗、再回頭修改的步驟；並讓使用者能跨裝置使用（例如手機開網頁、電腦打字）。

目標：

1. 讓使用者方便易寫，養成習慣
2. 提供 AI 批改功能
3. 盡可能以免費的方式提供

---

## 2. 系統架構

純前端網頁應用，**不建立任何後端服務**。

### 2.1 技術選型

| 項目 | 選擇 |
|---|---|
| 前端框架 | React |
| 建置工具 | Vite |
| 套件管理 | npm |
| 本機儲存 | 瀏覽器內的前端 DB（IndexedDB） |
| 跨裝置同步 | Google Drive（`drive.appdata` scope） |
| 認證 | Google 登入，僅用於取得 Drive 權限，不做帳號管理 |
| AI | Gemini API，使用者自備 API key |
| 單元測試 | Vitest |
| E2E 測試 | Playwright |
| 部署 | GitHub Pages，以 GitHub Actions 建置部署 |

### 2.2 語言

- App 介面語言為中文。
- 日記內容支援任何外語，僅支援純文字。
- 使用一份通用的 AI 提示詞模板，說明一律以中文顯示。
- 日記語言選項：自動判斷（預設）、日文、英文、其他（自行輸入）。

### 2.3 部署與本機開發

- push 到 `main` 時，GitHub Actions 自動安裝套件、執行測試、build、部署到 GitHub Pages；測試未通過不部署。
- 網址為 `https://<帳號>.github.io/<repo 名稱>/`，Vite 的 `base` 須設為 `/<repo 名稱>/`。
- 需處理 React 單頁應用在子路徑重新整理時的 404 問題。
- repo 為公開 repo，**嚴禁 commit 任何金鑰**。
- 本機開發使用 Vite 開發伺服器；build 產出的 `dist/` 不 commit。

## 3. 功能需求

### 3.1 日記

- 新增日記：以日期選擇器選擇日期（預設今天），輸入純文字內容後儲存。
- 內容空白時不儲存；只有空格、換行等空白字元也視為空白。
- 一天可以寫多篇。
- 列表依日期排序，同一天內依建立時間排序。
- 可以編輯與刪除。刪除前跳出確認視窗；刪除採軟刪除（見第 6 節），不提供垃圾桶復原功能。

### 3.2 AI 批改

- 日記頁有「AI 批改」按鈕，使用者按下才送出；儲存日記時不自動送出。
- 批改結果與日記顯示在同一頁：電腦上左右並排，手機上改為上下排列。
- **AI 批改結果僅供顯示，不得寫回或覆蓋日記原文。** 使用者看完建議後自行修改日記，修改後可再按按鈕重新批改。
- 每篇日記只保留最新一次的批改結果，重新批改時覆蓋舊結果。
- 詳細規則見第 5 節。

### 3.3 日曆

- 顯示在主畫面，不是獨立頁面：電腦上在旁邊，手機上在上方。
- 有寫日記的日期有顯著標示；可以像一般日曆一樣切換月份。
- 點選有日記的日期，顯示當天的日記列表並可開啟。
- 點選沒有日記的日期，不自動開啟新增日記。
- 已刪除的日記與範例日記不計入標示。

### 3.4 Google Drive 同步

不登入也能使用全部功能；登入 Google 後啟用同步。規則見第 6 節。

### 3.5 範例資料

- 首次開啟時預載一篇範例日記與已完成的 AI 批改結果，不需要 API key 即可看到完整效果。
- 範例須清楚標示為「範例」。
- 範例只存在本機，不參與 Google Drive 同步。
- 使用者可以刪除範例，刪除前同樣跳出確認視窗。範例刪除時直接從本機移除，不採軟刪除、不保留刪除記號；以設定中的 `sampleDismissed` 確保刪除後不再出現。

### 3.6 設定頁

- 輸入、修改、刪除 Gemini API key，並附申請 API key 的說明。
- 登入／登出 Google 並授權 Drive 存取（Phase 4）。
- 手動同步按鈕與同步狀態顯示（Phase 4）。

## 4. 資料模型

### 4.1 日記（DiaryEntry）

| 欄位 | 說明 |
|---|---|
| `id` | 唯一識別碼（UUID），同步時判斷是否為同一篇 |
| `date` | 使用者選擇的日記日期 |
| `content` | 純文字內容 |
| `language` | 日記語言：`auto`（預設）、日文、英文，或使用者自行輸入的語言 |
| `createdAt` | 建立時間，同日多篇排序用 |
| `updatedAt` | 最後修改時間，同步時比較新舊；任何修改（含刪除）都要更新 |
| `deleted` | 刪除標記 |
| `deletedAt` | 刪除時間，用於 90 天後清除 |
| `isSample` | 是否為範例日記 |
| `analysis` | 最新一次的 AI 批改結果（見 4.2），可為空 |

刪除時立即清除 `content` 與 `analysis`，只保留 `id`、`updatedAt`、`deleted`、`deletedAt`。

範例日記（`isSample` 為 true）例外：刪除時直接移除整筆資料，不保留刪除記號（見 3.5）。

**Phase 1 就必須包含 `id`、`updatedAt`、`deleted`、`deletedAt` 欄位，刪除從一開始就採用軟刪除**，避免 Phase 4 時大幅修改資料結構。

### 4.2 AI 批改結果（Analysis）

| 欄位 | 說明 |
|---|---|
| `detectedLanguage` | AI 判斷的日記語言 |
| `grammarErrors` | 文法錯誤列表，每項包含 `original`、`corrected`、`explanation`；無錯誤時為空陣列，畫面顯示「無錯誤」 |
| `unclearSentences` | 不通順或易誤會的句子，每項包含 `original`、`suggestion`、`explanation` |
| `naturalExpressions` | 更道地的說法，每項包含 `original`、`alternatives`（1～2 個）、`explanation` |
| `correctedText` | 修改後全文，以 `**` 標示修改處 |
| `translation` | 修改後全文的中文翻譯 |
| `analyzedAt` | 批改時間 |

### 4.3 設定（Settings）

| 欄位 | 說明 |
|---|---|
| `geminiApiKey` | 使用者的 Gemini API key；Phase 4 起隨 Drive 同步 |
| `sampleDismissed` | 範例是否已被刪除，用於確保刪除後不再出現；只存在本機 |

## 5. AI 整合

### 5.1 服務與 API key

- 使用 Gemini API，由使用者到 Google AI Studio 自行申請 API key 並填入設定頁。
- 未設定 API key 時按批改按鈕，提示使用者先到設定頁設定。
- 不提供開發者的 key，不建立中間層。

### 5.2 回傳格式

- 使用 Gemini 的 JSON 輸出功能，依 4.2 的欄位回傳。
- 回傳內容須先解析與驗證，格式不符時視為錯誤。

### 5.3 錯誤處理

- API 呼叫失敗（key 錯誤、網路問題、額度用完）或回傳格式錯誤時，顯示清楚的錯誤訊息，不影響日記本身。
- 不自動重試，由使用者自行再按一次。

### 5.4 安全規則

- **AI 回傳內容不得以原始 HTML 渲染。** 不使用 `dangerouslySetInnerHTML`；`**` 粗體標示須以安全的方式轉換顯示，若使用 Markdown 轉換套件，須關閉原始 HTML 支援。
- API key 只存在使用者的瀏覽器與其 Google Drive，不得送往 Gemini API 以外的任何地方，不得寫入 log。

### 5.5 提示詞模板

變數：
- `{{LANGUAGE_INSTRUCTION}}`：語言為 `auto` 時填入「請先判斷日記使用的語言。」；有指定時填入「這篇日記使用的語言是{語言}。」
- `{{DIARY}}`：日記內容

```text
你是一位外語寫作老師。使用者正在學習外語，以下是他用外語撰寫的日記。{{LANGUAGE_INSTRUCTION}}

請分析這篇日記，提出以下項目：

1. 文法錯誤：附上正確或恰當的修改。若無明顯錯誤，此項回傳空陣列。
2. 句子不通順或可能造成誤會之處：附上恰當的修改建議。
3. 更貼近母語者日常使用的說法：針對日記中使用的句子或詞彙，若有更自然的說法，個別推薦 1 至 2 個範例。

規則：

- 日記中允許口語化的用法，不需要改成書面語。
- 分析須提供詳細的說明，並配合你從日記中判斷出的使用者程度。
- 所有說明一律使用繁體中文。
- 提供修改後的完整日記，以 ** 標示修改處。
- 提供修改後日記的中文翻譯。
- 只依指定的 JSON 格式回傳，不要加入其他文字。

日記內容：
"""
{{DIARY}}
"""
```

## 6. Google Drive 同步規則

- **本機優先**：不登入也能寫日記，資料存在瀏覽器；登入 Google 後才啟用同步。
- **儲存位置**：使用 `drive.appdata` scope，存在使用者 Drive 的 App 專屬隱藏資料夾。
- **同步內容**：日記與 Gemini API key。範例日記不同步。
- **合併**：不同篇日記全部保留；同一篇（相同 `id`）兩邊都有修改時，以 `updatedAt` 較新者為準。
- **刪除**：軟刪除，刪除記號保留 90 天；於同步時檢查，超過 90 天的記號從本機與 Drive 一併清除。
- **同步時機**：開啟 App、儲存日記後自動同步；另提供手動同步按鈕，並顯示同步狀態（已同步／同步中／同步失敗）。
- **離線**：離線時儲存的日記，於恢復網路後的下一次同步一起補上。
- **授權過期**：能重新取得授權，或提示使用者重新登入，不得默默同步失敗。

已知限制（已接受，不需處理）：
- 比較時間依賴各裝置時鐘，時鐘不準時可能選錯版本。
- 裝置超過 90 天未同步時，已刪除的日記可能復活。

## 7. 測試

- 以下核心邏輯以 **TDD** 進行（先寫單元測試再實作）：
  - 日記排序
  - 軟刪除與 90 天清除
  - 同步合併規則
  - AI 回傳 JSON 的解析與驗證
- 畫面排版與外部服務串接（Gemini、Google Drive、IndexedDB）不強制 TDD，實作後視需要補單元測試。
- E2E 測試中，AI 回應一律使用模擬資料，不實際呼叫 Gemini API。

## 8. Phase 規劃

| Phase | 內容 | 階段成果 |
|---|---|---|
| 1. 基礎日記 | 專案建置、日記新增／編輯／刪除、排序、本機儲存、範例資料、部署 | 可以在網址上寫日記、看到範例 |
| 2. AI 批改 | API key 設定與說明、語言選擇、提示詞模板、JSON 解析、批改結果顯示 | 可以用 Gemini 批改日記 |
| 3. 日曆 | 主畫面日曆 | 可以從日曆看寫作紀錄 |
| 4. Google Drive 同步 | Google 登入、同步、合併與刪除清除、同步狀態 | 可以跨裝置使用 |

Phase 分支命名為 `dev/phase-<編號>`，phase 結束時以一般 merge（非 squash）合併回 `main`。

### 8.1 Phase 1 驗收條件

1. 可以新增日記：以日期選擇器選擇日期（預設今天）、輸入純文字內容、儲存
2. 內容空白時不儲存（只有空白字元也視為空白）
3. 同一天可以新增多篇日記
4. 日記列表依日期排序，同一天依建立時間排序
5. 可以編輯和刪除日記；刪除前跳出確認視窗；刪除採軟刪除，立即清除內文，畫面上不再顯示
6. 重新整理或關閉瀏覽器後再打開，日記仍然存在
7. 首次開啟時有一篇標示為「範例」的日記，可以刪除，刪除後不再出現
8. 網站已部署，可透過公開網址存取，且 `main` 更新後自動部署
9. 核心邏輯（排序、軟刪除）的單元測試全部通過
10. 主要流程（新增 → 儲存 → 重新整理後仍存在）有 E2E 測試且通過
11. README 包含：App 簡介、部署網址、技術選型、本機安裝與執行方式、測試執行方式

### 8.2 Phase 2 驗收條件

1. 設定頁可以輸入、修改、刪除 Gemini API key，並有申請說明
2. 未設定 API key 時按批改按鈕，提示使用者先到設定頁設定
3. 按下「AI 批改」按鈕才送出；儲存日記時不自動送出
4. 可以選擇日記語言：自動判斷（預設）、日文、英文、其他（自行輸入）
5. 批改結果依 4.2 的欄位顯示，文法錯誤為空時顯示「無錯誤」，修改後全文的修改處以粗體顯示
6. 電腦上批改結果與日記左右並排，手機上上下排列
7. 批改結果不會修改日記原文；修改日記後可重新批改，新結果覆蓋舊結果
8. 批改結果會儲存，重新打開日記仍可看到
9. API 呼叫失敗或回傳格式錯誤時顯示清楚的錯誤訊息，不影響日記本身，不自動重試
10. AI 回傳內容不以原始 HTML 渲染
11. JSON 解析與驗證的單元測試通過；批改流程有 E2E 測試且通過（使用模擬的 AI 回應）

### 8.3 Phase 3 驗收條件

1. 日曆顯示在主畫面：電腦上在旁邊，手機上在上方
2. 有寫日記的日期有顯著標示
3. 可以切換月份
4. 點選有日記的日期，顯示當天的日記列表並可開啟
5. 點選沒有日記的日期，不自動開啟新增日記
6. 已刪除的日記與範例日記不計入標示
7. 日曆標示邏輯的單元測試通過；有 E2E 測試且通過

### 8.4 Phase 4 驗收條件

1. 未登入時所有功能正常使用，資料只存在本機
2. 設定頁可以登入 Google 並授權 Drive 存取（`drive.appdata`），也可以登出
3. 登入後本機與 Drive 的日記依第 6 節規則合併
4. API key 隨日記同步，在另一台裝置登入後可直接使用
5. 刪除的日記同步到其他裝置後也不顯示，不會復活
6. 超過 90 天的刪除記號於同步時從本機與 Drive 清除
7. 開啟 App、儲存日記後自動同步；有手動同步按鈕；顯示同步狀態
8. 離線時儲存的日記，於恢復網路後的下一次同步補上
9. 範例日記不參與同步
10. Google 授權過期時能重新取得或提示重新登入，不會默默同步失敗
11. 合併、軟刪除、90 天清除的單元測試通過；以兩個瀏覽器模擬兩台裝置的同步流程有測試且通過

### 8.5 Phase 4 前置作業（由使用者處理）

以下事項由使用者在 Phase 4 開始前確認與設定。**未完成前，不要自行處理或假設結果**：

- 在 GCP 建立 OAuth 用戶端，登記已授權的 JavaScript 來源：`https://<帳號>.github.io` 與本機開發網址
- 確認 Google OAuth 正式發布的驗證要求（首頁、隱私權政策、網域所有權），以及 `github.io` 網域是否可通過驗證

OAuth 用戶端 ID 不是秘密，可以放在程式碼中；但仍不得 commit 任何 API key。
